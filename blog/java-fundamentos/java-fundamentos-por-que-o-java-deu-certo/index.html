Java Fundamentos: por que o Java deu certo

Explicação sobre os motivos técnicos que ajudaram Java a crescer, com foco em portabilidade, JVM, bytecode e arquivos .class.

Série

Java Fundamentos Parte 6 de 6

Java ganhou força porque sua proposta de portabilidade resolvia um problema importante: executar software em ambientes diferentes com menos dependência da plataforma.

O contexto do Java

Java foi apresentado publicamente em 1995, em um período de forte crescimento da internet.

A proposta da linguagem estava muito ligada à portabilidade.

Ou seja, a ideia era permitir que programas Java pudessem ser executados em diferentes sistemas operacionais e arquiteturas, desde que existisse uma JVM compatível naquele ambiente.

Esse ponto é importante: Java não roda automaticamente em qualquer máquina sem preparação.

Ele depende de uma Máquina Virtual Java adequada para executar o bytecode.

A portabilidade do Java

A portabilidade do Java está diretamente ligada à JVM, sigla para Java Virtual Machine.

A JVM pode existir em diferentes sistemas operacionais e servidores.

Com isso, um mesmo programa Java pode ser executado em ambientes diferentes sem que o programador precise reescrever todo o código para cada sistema.

Essa separação foi uma das grandes vantagens da linguagem.

Como o código Java funciona

O programador escreve um arquivo com código Java.

Esse código possui comandos, regras de sintaxe e significado definidos pela linguagem.

Esse é o código que conseguimos ler e escrever como desenvolvedores.

Depois, esse código passa pela compilação.

A compilação verifica regras da linguagem e transforma o código-fonte em um formato intermediário que a JVM consegue executar.

O arquivo .class

Depois da compilação, o Java gera arquivos .class.

Um arquivo .class segue um formato específico e contém informações da classe, além de instruções chamadas bytecodes.

Esses bytecodes não foram feitos para serem lidos diretamente por humanos no dia a dia.

Eles são instruções compreendidas pela JVM.

De forma simples:

.java  -> código-fonte Java
.class -> arquivo gerado pela compilação, com bytecodes

O papel dos bytecodes

Bytecodes são instruções intermediárias.

Eles não dependem diretamente de um único sistema operacional, como aconteceria com um executável nativo específico de uma plataforma.

A JVM entende esses bytecodes e executa o programa no ambiente onde está instalada.

Em uma explicação introdutória, podemos dizer que a JVM interpreta bytecodes.

Mas, em JVMs modernas, partes do programa também podem ser otimizadas e compiladas durante a execução.

Por que isso ajudou Java a crescer

Essa arquitetura ajudou Java a se tornar uma linguagem relevante porque reduziu o acoplamento direto entre o programa e o sistema operacional.

O desenvolvedor escreve o código Java e compila para bytecode.

Depois, uma JVM compatível executa esse bytecode em diferentes ambientes.

Isso facilitou o uso de Java em cenários variados, como aplicações corporativas, servidores, sistemas web e softwares de grande porte.

Recapitulando

Java deu certo por vários motivos, mas a portabilidade foi um dos mais importantes.

A ideia central é:

  1. o desenvolvedor escreve código Java;
  2. o código é compilado;
  3. a compilação gera arquivos .class;
  4. os arquivos .class contêm bytecodes;
  5. a JVM executa esses bytecodes;
  6. o programa pode rodar em diferentes ambientes com JVM compatível.

Essa combinação tornou Java uma linguagem forte para sistemas que precisam funcionar em plataformas diferentes.
